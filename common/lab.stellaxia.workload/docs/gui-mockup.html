>_node-aWorkload · 승격 데몬쓰기 일부 잠김

원천 register / update / start / restart 의 403 WORKLOAD_DAEMON_ELEVATED (Q-14 · D-27). 읽기 · stop · delete 는 그대로 됨.

승격 데몬Terra 데몬이 관리자(Windows) 또는 root(Linux) 권한으로 돌고 있어, 여기서 등록한 프로그램이 이 노드 사용자보다 높은 권한으로 실행될 수 있습니다. 그래서 등록 · 수정 · 시작 · 재시작을 막았습니다.데몬을 비승격으로 돌리면 이 띠는 저절로 사라집니다 — 이 화면에서 풀 방법은 없습니다.
잠긴 것과 열린 것
조작상태이유
+ 등록잠김 : 데몬 승격 — 등록 불가
수정잠김 : 데몬 승격 — 수정 불가
시작 · 재시작 잠김 : 데몬 승격 — 실행 불가
정지열림 — 이미 도는 것은 멈출 수 있음
해제열림 — 승격 아래 남은 등록을 치우는 길
목록 · 상세 · 로그 · 이력열림
언제 띠가 서나

계약에 승격 여부를 미리 묻는 읽기 operation 이 없습니다(health.get 은 status · version 뿐). 그래서 제안: ① 쓰기가 한 번 WORKLOAD_DAEMON_ELEVATED 로 거부되면 그 노드에 띠를 세우고 단추를 잠급니다. ② 잠긴 동안은 30초마다 가벼운 쓰기를 부르지 않고 단추를 눌렀을 때만 다시 확인합니다(오탐 방지). ③ 코어가 health.get 에 elevated 를 더하면 처음부터 띠를 세웁니다(간극 G1).

거부 응답 예 (그대로 옮김)
POST …/workloads/local.scriba-backend/start   →  403
{ "code": "WORKLOAD_DAEMON_ELEVATED",
  "message": "the Terra daemon runs elevated (Windows administrator / Linux root), so a registered program would run with more authority than the node's user; workloads are refused until the daemon runs unelevated (Q-14, D-27)" }

판별을 읽지 못한 경우도 승격으로 간주해 같은 코드로 거부됩니다 — 메시지가 "could not determine …" 로 시작하면 띠 아래 줄에 그 문장을 그대로 보여 줍니다.
