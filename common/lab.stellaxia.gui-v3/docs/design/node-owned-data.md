# 노드의 GUI 데이터는 그 노드가 원본

## 1. 한 줄

어떤 노드의 프로필 · 스킨은 **그 노드에 저장된다**. 어디서 바꾸든 그 노드를 먼저 고치고, 다른 노드와 다른 PC의 화면은 그 노드에서 읽어 갱신한다. 화면에 보이는 값은 그 노드의 값이어야 하고, 분할된 노드는 표시만 하고 바꾸지 못한다.

## 2. 무엇이 잘못돼 있었나 (2026-11-08 확인)

설정 창은 프로필과 스킨을 변경한 PC의 브라우저(`localStorage`의 `terra.fs` · `terra.skin`)에만 썼고, 장면도 거기서만 읽었다. 시안의 저장 흉내가 실제 빌드에 그대로 남은 것이다. 백엔드(`node-props` · `node-files`)는 있었지만 앱이 부르지 않았고, 서버와 이 PC의 `module-data/lab.stellaxia.gui-v3/node-data`는 비어 있었다. 데스크톱에서 서버의 프사를 바꿔도 서버에는 아무것도 가지 않았다.

백엔드를 그대로 불러도 다른 노드에서는 닿지 않았다.

| 막힌 곳 | 왜 | 고친 것 |
| --- | --- | --- |
| 원격 공개 | operation의 `availability.scopes`에 `cluster`가 없으면 대상 노드가 `OPERATION_NOT_REMOTE`로 거절한다 | 속성 · 파일 operation에 `cluster` 추가 |
| 권한 | 계약의 `gui-v3.view` · `gui-v3.customize`는 앱 선언에도 기본 사용자 권한에도 없다 | 읽기 `node.read`, 쓰기 `node.control` (nodetalk · fleet와 같은 어휘, 앱이 이미 가진 권한) |
| 응답 크기 | 다른 노드 응답은 768 KiB로 잘린다 | `node-files.get`에 `offset` · `limit` — 480 KiB씩 읽는다 |
| 형식 | 저장소는 이미지만 받는다 | `skin/*.json`은 `format: terra.sphere`인 구 파일(스타메이커 출력, Sheet 명세 terra.sphere v1)만 받는다. 첫 판이 보던 `type: terra.sphere`도 호환으로 받는다 |

쓰기를 `node.config`로 하지 않은 까닭: `node.config`는 소유권을 정하는 권한이라 기본 사용자에게 없고, 다른 노드로 부를 수 있어야 하는 이 값에는 무겁다. 값의 영향은 그 노드의 GUI 표시까지다.

## 3. 규칙

| 상황 | 동작 |
| --- | --- |
| 쓰기 | 그 노드의 지금 값을 읽고 → 파일을 올리고 → 속성표를 고친다. 다 성공해야 사본을 바꾼다(낙관 없음). 지난 파일은 그 뒤에 지운다 |
| 읽기 (E/L) | 사본을 바로 보여 주고, 낡았으면(60초) 뒤에서 그 노드 값을 받아 바꾼다 |
| 분할 (P/A) | 마지막 사본을 "끊김 · 언제 사본 · 읽기 전용"으로 보여 준다. 쓰기는 거부하고 큐에 쌓지 않는다 |
| 사본 | 그 노드에서 받은 값만 담는다. 이 PC에서 쓴 값이 그 노드의 값처럼 보이는 길은 없다 |
| 파일 사본 | 경로에 시각이 들어 있어 내용이 바뀌지 않는다. 한 번 받으면 IndexedDB에 두고, 끊겨도 보인다. 로그아웃하면 지운다 |

분할을 서버에서 따로 거부할 필요는 없다. 끊긴 노드로 가는 호출은 Master 중계가 `NODE_OFFLINE` · `RELAY_NOT_CONNECTED`로 실패시키고, 쌓아 두는 곳이 없다. 저장소는 그 노드 자신의 것이라, 노드가 돌아오기 전에는 낡은 쓰기가 닿을 길이 없다. GUI 잠금은 이 실패를 미리 알려 주는 표시다. 시험은 잠금 없이 호출해도 사본이 바뀌지 않는 것까지 본다.

## 4. 저장 모양

```text
node-data/
├─ properties.json    { "profile": { "image": "/데이터/profile/image/<시각>-<파일>" },
│                       "skin":    { "file":  "/데이터/skin/<구 id>-<시각>.json" } }
├─ profile/image/…
└─ skin/<구 id>-<시각>.json   ← 적용할 때 보관함의 구 파일을 복사한 것
```

스킨은 적용할 때 구 파일을 그 노드로 **복사**한다. 어느 PC에서 봐도 같고, 보관함에서 원본을 지워도 노드의 스킨은 남는다.

## 5. 적용 범위 밖

| 항목 | 지금 | 비고 |
| --- | --- | --- |
| 스타메이커 보관함 | 이 브라우저 | 사람의 작업물이다. 적용한 스킨만 노드로 간다 |
| 계정 · 리소스 자리의 프사 · 스킨 | 저장할 Terra 노드가 없어 읽기 전용 | 리소스의 주인(리프)에 둘지는 정하지 않았다 |
| 제어기 바탕 구성(아이콘 · 모양 · 배경 그림) | 그 노드 `desk.json` · `desk/wall/` | 이 표의 범위 밖이 아니라 [[node-owned-desk]]의 규칙으로 옮겼다(0.6.0). 창 배치 · 터미널 기록은 PC별 |
| 설정 창의 표시 · 뷰 · 노드 설정 칸 | 창 안에서만, 저장되지 않음 | 시안 그대로 |

이미 브라우저에 있던 프사 · 스킨은 옮기지 않는다. 어느 PC의 값이 맞는지 알 수 없어, 옮기면 다른 노드 값을 덮을 수 있다. 한 번 다시 설정한다.

## 6. 섞인 버전

새 GUI가 옛 gui-v3 모듈이 도는 노드를 부르면 `OPERATION_NOT_REMOTE` 또는 `TYPE_DENIED`로 실패하고, 설정 창이 그 이유를 적는다. 사본은 바뀌지 않는다.
